# React в ChessTrainer: справочник для C#-разработчика

## С чего начать чтение

1. `src/main.tsx` — запускает React внутри HTML-страницы.
2. `src/App.tsx` — выбирает экран и хранит общий список партий.
3. `src/components/LocalGame.tsx` — управляет ручной партией.
4. `src/components/ChessBoard.tsx` — отображает позицию и получает действия пользователя.
5. `src/lib/localGame.ts`, `src/data/localGames.ts`, `src/lib/sounds.ts` — правила, хранение и звук.

`components` содержит UI, `lib` — функции и браузерные сервисы, `data` — демоданные и локальное хранение. Это организация файлов, а не отдельные сборки или DI-контейнер.

## Основные понятия

| Понятие | Знакомая аналогия | Как используется здесь |
| --- | --- | --- |
| TypeScript | Типизированный язык с интерфейсами | Проверяет контракт props и модели во время сборки; типы исчезают в JavaScript |
| React-компонент | Функция, описывающая представление | `LocalGame` возвращает JSX экрана |
| JSX, файл `.tsx` | Разметка с выражениями, отдалённо похожая на Razor | `<ChessBoard fen={chess.fen()} />` |
| Props | Параметры/DTO и делегаты | `fen` приходит сверху, `onMove` сообщает о ходе родителю |
| State | Состояние конкретного экземпляра UI | Массив `moves` и выбранная ориентация |
| Callback | `Action<T>` / `Func<T, TResult>` | `onSaved(game)` обновляет список в `App` |
| Promise | Приблизительный аналог `Task<T>` | `await file.text()` читает файл |

Компонент — обычная функция, которую React вызывает снова при обновлениях. Она описывает, каким должен быть UI при текущих props и state. React применяет нужные изменения к DOM — дереву элементов браузера. Рендер компонента не означает полную перезагрузку страницы.

## State и обновление экрана

```tsx
const [moves, setMoves] = useState<CoordinateMove[]>([])
setMoves((current) => [...current, newMove])
```

Первая строка через деструктуризацию получает текущее значение и функцию обновления. Второй вызов создаёт новый массив и запрашивает рендер. `current` — актуальное состояние, переданное React в функцию обновления.

Не используй `moves.push(newMove)` для обновления state: изменится старый массив, но React не получит корректного запроса на обновление. Props тоже следует считать входными данными только для чтения.

`setMoves(...)` не меняет переменную `moves` внутри уже выполняющегося обработчика. Этот обработчик видит снимок состояния своего рендера. Сетевой вызов или таймер может удерживать такой старый снимок через замыкание. [Объяснение снимков состояния](https://react.dev/learn/state-as-a-snapshot).

## Hooks, которые встретятся в коде

Hooks — функции React для состояния и взаимодействия с окружением. Вызывай их на верхнем уровне компонента, в одном порядке, вне условий и циклов.

- **`useState`** хранит данные, влияющие на UI. `useState(() => localGames.readDraft())` использует ленивый инициализатор. При обычных повторных рендерах чтение не выполняется заново; в разработке StrictMode может повторить инициализацию для проверки.
- **`useMemo`** переиспользует вычисленное значение, пока зависимости не изменились. В `LocalGame` из `moves` получается позиция. Это оптимизация, а не гарантия хранения: расчёт должен оставаться корректным при повторном запуске.
- **`useRef`** сохраняет объект с полем `.current` между рендерами. Изменение этого поля не вызывает рендер. `gameId` хранит идентификатор, `inputRef` — DOM-элемент. Это не C#-модификатор `ref`; обычно ref читают и меняют в обработчиках или эффектах. [Документация useRef](https://react.dev/reference/react/useRef).
- **`useEffect`** синхронизирует компонент с внешним окружением после обновления UI: запись черновика или подписка на клавиатуру. Массив зависимостей определяет повторный запуск. Возвращённый cleanup снимает подписку перед следующим запуском и при удалении компонента. Не нужен для обычного вычисления FEN из ходов. [Объяснение эффектов](https://react.dev/learn/synchronizing-with-effects).
- **`useSyncExternalStore`** подписывает UI на состояние вне React. Здесь общий звуковой модуль уведомляет обе кнопки переключения.

В `LocalGame` state отвечает за экран, а `movesRef` даёт обработчику сразу прочитать принятую историю до следующего рендера. Это локальный приём, который требует синхронно обновлять обе записи; дублировать весь state в ref не нужно.

## Как проходит один ход

```text
Клик / перетаскивание
  → ChessBoard.move(): проверка доступных ходов, при необходимости выбор превращения
  → callback onMove(from, to, promotion)
  → LocalGame.makeMove(): воспроизведение истории и применение хода через chess.js
  → новый массив moves → setMoves()
  → React снова вызывает LocalGame → новый FEN передаётся в ChessBoard
  → эффект сохраняет черновик
```

Звук запускается в обработчике принятого хода: мат имеет приоритет над шахом, шах над взятием, взятие над обычным ходом. Недопустимый ход возвращает `false`.

`react-chessboard` рисует фигуры и обрабатывает взаимодействие. `chess.js` проверяет легальность, рокировку, взятие на проходе и результат партии. Оценка позиции этим не вычисляется: она будет приходить от Stockfish через backend.

Отмена удаляет последний полуход; новая позиция получается воспроизведением оставшейся истории. PGN содержит эту историю и теги, FEN — только позицию с её служебными параметрами.

## Как читать JSX и TypeScript

```tsx
<ChessBoard fen={chess.fen()} onMove={makeMove} />
{notice && <p>{notice}</p>}
{rows.map((row) => <div key={row.number}>{row.white}</div>)}
```

В `{...}` находится JavaScript-выражение. `onMove={makeMove}` передаёт функцию, не вызывает её. `notice && ...` показывает элемент при непустом сообщении. `map` похож на LINQ `Select`, `filter` — на `Where`; `key` задаёт стабильную идентичность элемента списка. В `Review` смена `key={selectedGame.id}` создаёт новый экземпляр с новым state.

`{ from, to }` сокращает `{ from: from, to: to }`; `...object` копирует свойства; `?.` и `??` похожи на C#; `as Square` сообщает тип компилятору, но ничего не валидирует во время выполнения. Поэтому JSON из хранилища всё равно проверяется кодом.

## Где будущий backend

`localGames` сейчас хранит JSON в `localStorage` конкретного браузера. `onSaved` уведомляет `App`, но не отправляет данные на сервер. При появлении API адаптер станет асинхронным: понадобятся `await`, состояние ожидания и обработка ошибок. Анализ и тренер пока отключены.

## Быстрая проверка

Из папки `frontend`:

```bash
npm run dev   # Vite запускает локальный сервер и обновляет страницу при изменении файлов
npm run build # TypeScript проверяет типы, Vite собирает статические файлы в dist
npm test      # Проверяет правила и PGN; это не тесты React-интерфейса или воспроизведения аудио
```

В DevTools браузера Console показывает ошибки, Network — загрузку ресурсов и будущие HTTP-запросы. Для первого самостоятельного упражнения попробуй добавить отображение числа ходов в заголовке: возьми `moves.length`, не вводя новый state.
